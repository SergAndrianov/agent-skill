### Граничные случаи

| Случай | Результат разбора модели |
| --- | --- |
| Пустой или невалидный счёт | Сервер возвращает ошибку валидации до ГИС ЖКХ. |
| Полный ответ и ответ с отсутствующим сроком | Первый показывает полученные значения. Во втором срок обозначен как отсутствующий. Обе записи являются результатом успешного поиска. |
| Пустой успешный ответ без подтверждения и с подтверждением | Без подтверждения привязки нет. Явное подтверждение действительного результата сохраняет привязку и пустой успешный снимок по A-03. |
| Сбой поиска | Сервер предлагает повтор поиска и не выдаёт идентификатор подтверждения для этого запроса. |
| Подтверждение с изменёнными реквизитами, чужим или истёкшим идентификатором | Сервер использует реквизиты, проверенные при поиске. Чужой идентификатор отклоняется до записи. Истёкший идентификатор не позволяет начать новую привязку. |
| Повторное и параллельное подтверждение | Одна атомарная запись по ключу владельца и реквизитов. Повтор получает тот же идентификатор привязки. При уже завершённом подтверждении истечение срока поиска не меняет результат повтора. |
| Сбой обновления с прежним полным или пустым снимком и без снимка | Со снимком сервер возвращает его время и признак неактуальности. Без снимка возвращает ошибку без подстановки нулевой задолженности. |
| Запрос и изменение чужой привязки | Сервер не видит запись в области текущего владельца. Данные, запись и вызов источника отсутствуют. |

Проверки выше относятся к архитектурной модели. Исполняемое приложение в работу не входило. Контракты банковской сессии и ГИС ЖКХ предстоит подтвердить перед реализацией.
