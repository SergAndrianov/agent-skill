# Проверка границы ПлатиДома на C4 L2

| Фича и прогон | Внутри ПлатиДома | Снаружи | Результат проверки |
|---|---|---|---|
| Поиск, воспроизведение | Сервер, хранилище | Клиент, мобильное приложение, ГИС ЖКХ | Ошибка обнаружена. `mobile` объявлен внешней системой. [DSL](architecture-review/search/before.dsl) · [Рисунок](architecture-review/search/before.svg) |
| Поиск после исправления | Мобильное приложение, сервер, хранилище | Клиент, ГИС ЖКХ | Проверка пройдена. Участник обращается к внутреннему мобильному контейнеру. Все четыре связи поиска сохранены. [DSL](architecture-review/search/after.dsl) · [Рисунок](architecture-review/search/after.svg) |
| Автоплатеж с лимитом | Мобильное приложение, сервер, хранилище | Клиент, ГИС ЖКХ, система карт банка, процессинг | При построении второй фичи учтена ошибка границы из примера поиска. Проверка пройдена. На рисунке видны семь связей, включая отдельные поручение списания и запрос статуса. [DSL](architecture-review/workspace.dsl) · [Рисунок](architecture-review/Autopay.svg) |

У всех трёх видов один `person` — клиент. В обоих исправленных DSL `mobile` объявлен как `container` внутри `platidom`, тегу `Mobile` назначена форма `MobileDevicePortrait`. Проверены направление входа `client → mobile → api`, вложенность всех контейнеров и состав внешних систем. Положение элементов сверено на рисунках.

Ошибку для поиска воспроизвели по [версии PR №3 с внешним мобильным банком](https://github.com/SergAndrianov/agent-skill/blob/5a9b34768638263b665a8e5667e27d0a174b7861/artifacts/architecture-review/workspace.dsl). В исходных PR №1 и №2 мобильное приложение уже находилось внутри системы. [История ошибки и нарушенное правило](../ai-log.md).

Structurizr Playground v2026.10.01 отобразил оба варианта SearchAndLink и вид Autopay. Все три приложенных SVG построены локально из соответствующих DSL с фиксированным расположением узлов для сравнения. Штатный экспорт Playground недоступен для скачивания в этой сессии. Структуру обновлённого скилла проверил `quick_validate.py`.
