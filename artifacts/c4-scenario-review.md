Сравнение показывает обнаруженные расхождения, но не измеряет эффект одной только правки инструкции.

Для денежных примеров исходно установлены собственная привязка, активное правило с лимитом 100 RUB, неоплаченное начисление и достаточный остаток. В каждой строке меняется указанное условие.

| Вход или событие | Наблюдаемый результат в модели | Оценка |
|---|---|---|
| Пустой либо неверный счет | Сервер возвращает ошибку ввода до обращения в ГИС | Определено, 2164/2 |

| Обновление завершилось ошибкой, есть снимок | Снимок сохраняется, UI показывает его возраст через время последнего успешного обновления и отметку неактуальности | Определено, 2165/4 |

## Результат проверки скилла

Базовый прогон обнаружил пустые технологии и четыре связи без способа взаимодействия в PR №1, а также отсутствие изображений в обоих комплектах. Он воспроизвел основные сценарии и не выделил проблему валют и поиска операции без внешнего ID. В повторном прогоне проверяющий указал для обоих случаев конкретный недостающий контракт, отличил его от наблюдаемого результата и сохранил принятые решения без выдуманного курса конвертации или API. Сравнение сумм и результат считывания из документации не доказывают корректность платежного кода.

Для повторения взять указанные ревизии, дать проверяющему скилл и входы из первого столбца без ответов, затем сравнить результат с двумя правыми столбцами. Для неопределенных случаев допустимый результат — точный вопрос или явно помеченное предложение.
