# Глоссарий ПлатиДома

ПлатиДом — учебный продукт, раздел мобильного банка для регулярных начислений семьи. Эта база знаний охватывает поиск и привязку начислений по лицевому счету и автоплатеж с лимитом суммы. Термины описывают предметную область и не предписывают архитектуру.

| Термин | Определение |
|---|---|
| Клиент | Авторизованный пользователь мобильного банка, который ищет начисления, сохраняет привязки и управляет своими автоплатежами. |
| Поставщик | Организация, услуги которой оплачивает клиент и для которой задан лицевой счет. Не обязательно является системой, непосредственно передающей данные ПлатиДому. |
| Лицевой счет | Идентификатор учета услуг у выбранного поставщика. В этом контексте это не банковский счет и не источник списания денег. |
| Начисление | Полученное из внешнего источника требование к оплате, для которого могут быть переданы идентификатор, поставщик, сумма, валюта, срок оплаты и состояние. |
| Идентификатор начисления | Идентификатор, позволяющий отличать начисление и сопоставлять его с платежом. Область уникальности между внешними источниками требует уточнения. |
| Источник начислений | Внешняя система, из которой ПлатиДом получает сведения о начислениях. ГИС ЖКХ рассматривается как учебное допущение. |
| Поиск начислений | Получение начислений по выбранному поставщику и лицевому счету. Сам по себе не создает привязку. |
| Привязка | Сохраненная связь клиента с лицевым счетом у поставщика, позволяющая запрашивать начисления без повторного ввода реквизитов. Уникальная комбинация: клиент + поставщик + лицевой счет. |
| Владелец привязки | Клиент, в профиле которого сохранена привязка. Это не утверждение о юридическом владении помещением или лицевым счетом. |
| Актуальные начисления | Данные, которые система считает пригодными для принятия решения об оплате. Способ проверки и допустимый возраст данных пока не определены. |
| Источник оплаты | Доступный клиенту платежный инструмент, выбранный для автоплатежа. Конкретный вид инструмента пока не зафиксирован. |
| Автоплатеж | Автоматическая оплата начисления по ранее подтвержденному клиентом правилу при выполнении обязательных проверок. |
| Правило автоплатежа | Настройка для привязки: источник оплаты, лимит, согласие клиента и состояние активности. |
| Лимит | Максимальная разрешенная сумма одного начисления для автоплатежа. В учебном сценарии задается в рублях; включительно допускает сумму, равную лимиту. |
| Согласие на автоплатеж | Явное подтверждение клиентом настройки автоматической оплаты. Способ подтверждения и доказательства согласия пока не определены. |
| Попытка оплаты | Отслеживаемая обработка оплаты конкретного начисления, включая отправку запроса и выяснение результата. Повторная проверка результата не означает новый платеж. |
| Процессинг | Внешняя система, принимающая запрос оплаты и предоставляющая результат операции. |
| Идентификатор операции | Идентификатор платежной операции, используемый для сопоставления запроса с результатом и проверки состояния. |
| Защита от повторного списания | Требование, при котором повторные события и параллельные обработки не создают повторную оплату одного начисления. Конкретный механизм предстоит спроектировать. |
| Пропуск автоплатежа | Решение не отправлять оплату, поскольку условия не выполнены, например превышен лимит. Отличается от отказа процессинга после отправки. |
| Результат уточняется | Состояние попытки, когда достоверный итог неизвестен. Требуется проверка исходной операции; новую оплату отправлять нельзя. |
