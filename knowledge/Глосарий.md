**Уровень 1: Контекст (Context)**
- Контекст (Context). Самый верхний уровень. Показывает, как система вписывается в внешний мир: кто в ней участвует (пользователи, внешние сервисы) и с чем она взаимодействует.
- System Context Diagram — высокоуровневая схема, которая показывает систему как единый блок в окружении пользователей и других систем, а также потоки данных или API-вызовы между ними.
- Пользователь (Person) — роль или человек (внешняя сущность), взаимодействующий с системой (например, клиент, оператор, администратор).
- Актор (Actor) — синоним для _Person_ на уровне контекста.
- Внешняя система (External System) — уже существующая IT-система, с которой интегрируется целевая система.
- Связь (Relationship) — отношение взаимодействия между элементами на диаграммах (например, вызов API, обмен данными).
**Уровень 2: Контейнеры (Container)**
- Контейнер — исполняемый блок внутри системы., который может работать независимо (веб-приложение, API-сервис, база данных, очередь сообщений).
**Уровень 3: Компоненты (Component)**
- Компонент — логическая часть внутри контейнера, которая реализует определённую функциональность (модуль, сервис, репозиторий).
- Интерфейс (Interface) — контракт, который компонент предоставляет другим частям системы для взаимодействия с ним.
**Уровень 4: Код (Code)**
- Код — самый детальный уровень. Здесь показывают элементы реализации: классы, интерфейсы, функции, зависимости между ними. Часто для этого уровня опираются на другие нотации — например, диаграммы классов UML или ERD, либо инструменты IDE могут автоматически сгенерировать такую диаграмму из исходного кода.
