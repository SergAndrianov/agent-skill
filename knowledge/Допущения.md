# Допущения ПлатиДома

| ID   | Допущение                                                                                                                                                                                              |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A-01 | Для выбранных фич рассматриваются начисления ЖКУ из ГИС ЖКХ. Поиск налогов и штрафов по документам не входит в выбранный объем.                                                                        |
| A-02 | Формат лицевого счета определяется поставщиком; универсальная длина не задается.                                                                                                                       |
| A-03 | Успешный поиск без начислений допускает привязку валидного лицевого счета. Проверка юридического владения и отвязка не входят в историю.                                                               |
| A-04 | Лимит — положительное число в рублях на одно начисление. Оплачивается вся сумма; частичная оплата исключена.                                                                                           |
| A-05 | Для одной привязки действует одно активное правило. Состояния: «активно» и «отключено». Повторное включение отключенного правила разрешается при повторном прохождении проверок.                       |
| A-06 | Перед оплатой проверяются владелец, актуальность и неоплаченность начисления, активность правила, сумма в пределах лимита и достаточность денег.                                                       |
| A-07 | Состояния попытки: «обрабатывается», «успешно», «отклонено», «результат уточняется». После проверки неизвестного результата допускается переход к подтвержденному успеху или отказу исходной операции. |
| A-08 | По одному начислению допускается не более одного успешного автоплатежа. Параллельные обработки и повторные события не создают повторных списаний.                                                      |
| A-09 | Процессинг позволяет распознавать повторы и проверять результат ранее отправленной операции. При неизвестном результате сначала выполняется проверка, новый платеж не отправляется.                    |
| A-10 | Результат или причина пропуска доступны клиенту внутри приложения. Другие каналы уведомлений не определены.                                                                                            |
| A-11 | Изменения настроек применяются к попыткам, еще не переданным в процессинг. Уже отправленная попытка продолжает отслеживаться.                                                                          |
| A-12 | В учебном сценарии оплата передается в процессинг карт. Точные протоколы внешних систем не задаются.                                                                                                   |
| A-13 | Сохраняются идентификатор начисления, поставщик, сумма, валюта, срок и состояние, если они получены от источника.                                                                                      |

## Вопросы без принятого решения

| ID   | Что уточнить                                                                                                         | Почему важно                                                            |
| ---- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Q-01 | Когда запускается автоплатеж: сразу при обнаружении начисления, по расписанию или перед сроком оплаты?               | Определяет момент запуска сценария. В текущих требованиях ответа нет.   |
| Q-02 | Как определяется актуальность начисления и что делать при изменении суммы?                                           | Нужно исключить оплату устаревшей суммы.                                |
| Q-03 | Каковы тайм-ауты, периодичность и предел проверки неизвестного результата? Что происходит после исчерпания проверок? | Состояние «результат уточняется» пока не имеет регламента завершения.   |
| Q-04 | Допустима ли новая попытка после окончательного отказа, и при каких условиях?                                        | Защита от дублей не описывает политику повторной оплаты после отказа.   |
| Q-05 | Каковы область уникальности идентификатора начисления и срок защиты от повторной оплаты?                             | Разные источники могут использовать совпадающие идентификаторы.         |
| Q-06 | Какие источники оплаты доступны? Входит ли комиссия в лимит и проверку достаточности средств?                        | Текущие требования не определяют комиссию и тип платежного инструмента. |
| Q-07 | Как клиент подтверждает согласие и что сохраняется в качестве его доказательства?                                    | Механизм и срок хранения согласия не описаны.                           |
| Q-08 | Чем подтверждаются валидность и принадлежность лицевого счета?                                                       | Нужна согласованность A-03 и требований к доступу.                      |
| Q-09 | Как обрабатываются запоздалые ответы процессинга и противоречивые результаты?                                        | Переходы после уже зафиксированного результата не определены.           |
