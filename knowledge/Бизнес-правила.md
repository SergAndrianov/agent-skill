# Бизнес-правила ПлатиДома
## Доступ и поиск начислений

| ID    | Правило                                                                                                                                                                                       |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| BR-01 | Получать начисления может только авторизованный клиент. Привязки, правила автоплатежа и операции доступны только их владельцу. Чужие данные не раскрываются.                                  |
| BR-02 | Для поиска нужны выбранный поставщик и непустой лицевой счет, корректный по правилам этого поставщика. При ошибке ввода запрос источнику не отправляется.                                     |
| BR-03 | Полученные сумма, валюта, срок оплаты и поставщик показываются клиенту. Отсутствующие сведения обозначаются как отсутствующие и не выдумываются.                                              |
| BR-04 | Успешный ответ без начислений и ошибка источника — разные исходы. Ошибка не означает отсутствие задолженности; клиент может повторить поиск.                                                  |
| BR-05 | Поиск не создает привязку автоматически. Для сохранения требуется явное подтверждение клиента после успешного поиска.                                                                         |
| BR-06 | Для комбинации клиент + поставщик + лицевой счет сохраняется одна привязка. Повторное подтверждение возвращает существующую привязку без дубля.                                               |
| BR-07 | Сохраненная привязка доступна при следующем входе и позволяет запросить начисления без повторного ввода лицевого счета.                                                                       |
| BR-08 | При ошибке обновления ранее полученные данные, если они есть, показываются как неактуальные с временем последнего успешного обновления. Нулевая задолженность вместо ошибки не подставляется. |

## Управление автоплатежом

| ID    | Правило                                                                                                                                                                                              |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| BR-09 | Для активации нужны собственная привязка, доступный источник оплаты, положительный числовой лимит в рублях и согласие клиента. При нарушении проверки правило не активируется; показывается причина. |
| BR-10 | На одну привязку допускается одно активное правило. Повторное включение или изменение не создает дубликат; сохраняется новая подтвержденная конфигурация.                                            |
| BR-11 | Отключенное правило не запускает новые попытки. Уже отправленная в процессинг попытка продолжает отслеживаться; отключение не обещает отмену списания.                                               |

## Исполнение автоплатежа

| ID    | Правило                                                                                                                                                                                                  |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| BR-12 | Перед отправкой проверяются принадлежность привязки клиенту, актуальность и неоплаченность начисления, активность правила, положительная сумма в пределах лимита и достаточность средств.                |
| BR-13 | Лимит применяется к одному начислению. Сумма, равная лимиту, разрешена; превышающая лимит — нет. Частичная оплата исключена.                                                                             |
| BR-14 | При превышении лимита, нехватке средств, отключенном правиле или уже оплаченном начислении запрос оплаты не отправляется; клиент видит причину пропуска.                                                 |
| BR-15 | Повторные события, повторный запуск и параллельная обработка не должны приводить к повторному списанию по одному начислению. Повторная обработка используется для выяснения результата исходной попытки. |
| BR-16 | Успех фиксируется только после подтверждения процессинга и показывается с суммой и идентификатором операции. Явный отказ показывается как «отклонено» с причиной.                                        |
| BR-17 | Тайм-аут или потеря ответа переводят попытку в состояние «результат уточняется». Проверяется исходная операция; новый платеж не отправляется, неподтвержденный успех не показывается.                    |
| BR-18 | Результат оплаты либо причина пропуска доступны клиенту в приложении только для собственных операций.                                                                                                    |

## Состояния и переходы

### Правило автоплатежа

| Исходное состояние  | Событие и условие                                    | Результат                                |
| ------------------- | ---------------------------------------------------- | ---------------------------------------- |
| Правило отсутствует | Клиент подтверждает корректную настройку             | Активно                                  |
| Активно             | Клиент подтверждает изменение параметров             | Активно с новой конфигурацией, без дубля |
| Активно             | Клиент отключает правило                             | Отключено                                |
| Отключено           | Клиент вновь включает правило, все проверки пройдены | Активно                                  |

Состояние «правило отсутствует» означает отсутствие настройки, а не отдельный хранимый статус.
### Попытка оплаты

| Исходное состояние   | Событие                                                     | Следующее состояние  |
| -------------------- | ----------------------------------------------------------- | -------------------- |
| Попытка отсутствует  | Проверки пройдены, начинается обработка                     | Обрабатывается       |
| Обрабатывается       | Процессинг подтвердил успех                                 | Успешно              |
| Обрабатывается       | Процессинг явно отказал                                     | Отклонено            |
| Обрабатывается       | Тайм-аут или потеря ответа                                  | Результат уточняется |
| Результат уточняется | Получено достоверное подтверждение успеха исходной операции | Успешно              |
| Результат уточняется | Получен достоверный отказ по исходной операции              | Отклонено            |
| Результат уточняется | Достоверного результата все еще нет                         | Результат уточняется |

Пропуск до отправки не равен отказу процессинга. Хранить ли пропуск как отдельную попытку, пока не решено. Отмена, возврат и повторная оплата после явного отказа не описаны требованиями; переходы для них не следует придумывать.

Для начислений текущие требования различают оплаченные и неоплаченные данные, но полного перечня статусов и переходов нет. Для привязки жизненный цикл удаления и восстановления также не определен.
