# Бизнес-правила ПлатиДома

Правила относятся к двум выбранным фичам. Источник каждого правила указан явно. Правила из критериев приемки действуют как требования текущей версии Jira; наличие их в карточках само по себе не означает подтверждения ментором. Допущения хранятся в [assumptions.md](assumptions.md).

## Доступ и поиск начислений

| ID | Правило | Источник |
|---|---|---|
| BR-01 | Получать начисления может только авторизованный клиент. Привязки, правила автоплатежа и операции доступны только их владельцу. Чужие данные не раскрываются. | SCRUM-2164–2168 |
| BR-02 | Для поиска нужны выбранный поставщик и непустой лицевой счет, корректный по правилам этого поставщика. При ошибке ввода запрос источнику не отправляется. | SCRUM-2164, критерии 1–2 |
| BR-03 | Полученные сумма, валюта, срок оплаты и поставщик показываются клиенту. Отсутствующие сведения обозначаются как отсутствующие и не выдумываются. | SCRUM-2164, критерий 1 |
| BR-04 | Успешный ответ без начислений и ошибка источника — разные исходы. Ошибка не означает отсутствие задолженности; клиент может повторить поиск. | SCRUM-2164, критерии 3–4 |
| BR-05 | Поиск не создает привязку автоматически. Для сохранения требуется явное подтверждение клиента после успешного поиска. | SCRUM-2164, критерий 3; SCRUM-2165, критерий 1 |
| BR-06 | Для комбинации клиент + поставщик + лицевой счет сохраняется одна привязка. Повторное подтверждение возвращает существующую привязку без дубля. | SCRUM-2165, критерий 2 |
| BR-07 | Сохраненная привязка доступна при следующем входе и позволяет запросить начисления без повторного ввода лицевого счета. | SCRUM-2165, критерий 3 |
| BR-08 | При ошибке обновления ранее полученные данные, если они есть, показываются как неактуальные с временем последнего успешного обновления. Нулевая задолженность вместо ошибки не подставляется. | SCRUM-2165, критерий 4 |

## Управление автоплатежом

| ID | Правило | Источник |
|---|---|---|
| BR-09 | Для активации нужны собственная привязка, доступный источник оплаты, положительный числовой лимит в рублях и согласие клиента. При нарушении проверки правило не активируется; показывается причина. | SCRUM-2167, критерии 1–2; A-04 |
| BR-10 | На одну привязку допускается одно активное правило. Повторное включение или изменение не создает дубликат; сохраняется новая подтвержденная конфигурация. | SCRUM-2167, критерий 3; SCRUM-2166 |
| BR-11 | Отключенное правило не запускает новые попытки. Уже отправленная в процессинг попытка продолжает отслеживаться; отключение не обещает отмену списания. | SCRUM-2167, критерий 4 |

## Исполнение автоплатежа

| ID | Правило | Источник |
|---|---|---|
| BR-12 | Перед отправкой проверяются принадлежность привязки клиенту, актуальность и неоплаченность начисления, активность правила, положительная сумма в пределах лимита и достаточность средств. | SCRUM-2166; SCRUM-2168, критерии 1–2 |
| BR-13 | Лимит применяется к одному начислению. Сумма, равная лимиту, разрешена; превышающая лимит — нет. Частичная оплата исключена. | SCRUM-2166; SCRUM-2168, критерий 1; A-04 |
| BR-14 | При превышении лимита, нехватке средств, отключенном правиле или уже оплаченном начислении запрос оплаты не отправляется; клиент видит причину пропуска. | SCRUM-2168, критерий 2 |
| BR-15 | Повторные события, повторный запуск и параллельная обработка не должны приводить к повторному списанию по одному начислению. Повторная обработка используется для выяснения результата исходной попытки. | SCRUM-2166; SCRUM-2168, критерий 3 |
| BR-16 | Успех фиксируется только после подтверждения процессинга и показывается с суммой и идентификатором операции. Явный отказ показывается как «отклонено» с причиной. | SCRUM-2168, критерий 4 |
| BR-17 | Тайм-аут или потеря ответа переводят попытку в состояние «результат уточняется». Проверяется исходная операция; новый платеж не отправляется, неподтвержденный успех не показывается. | SCRUM-2166; SCRUM-2168, критерий 5 |
| BR-18 | Результат оплаты либо причина пропуска доступны клиенту в приложении только для собственных операций. | SCRUM-2166; SCRUM-2168, критерий 6 |

## Состояния и переходы

### Правило автоплатежа

| Исходное состояние | Событие и условие | Результат | Основание |
|---|---|---|---|
| Правило отсутствует | Клиент подтверждает корректную настройку | Активно | SCRUM-2167 |
| Активно | Клиент подтверждает изменение параметров | Активно с новой конфигурацией, без дубля | SCRUM-2167 |
| Активно | Клиент отключает правило | Отключено | SCRUM-2167 |
| Отключено | Клиент вновь включает правило, все проверки пройдены | Активно | Детализация A-05; требует подтверждения |

Состояние «правило отсутствует» означает отсутствие настройки, а не отдельный хранимый статус.

### Попытка оплаты

| Исходное состояние | Событие | Следующее состояние | Основание |
|---|---|---|---|
| Попытка отсутствует | Проверки пройдены, начинается обработка | Обрабатывается | Детализация A-07 |
| Обрабатывается | Процессинг подтвердил успех | Успешно | SCRUM-2168 |
| Обрабатывается | Процессинг явно отказал | Отклонено | SCRUM-2168 |
| Обрабатывается | Тайм-аут или потеря ответа | Результат уточняется | SCRUM-2168 |
| Результат уточняется | Получено достоверное подтверждение успеха исходной операции | Успешно | Детализация A-07 |
| Результат уточняется | Получен достоверный отказ по исходной операции | Отклонено | Детализация A-07 |
| Результат уточняется | Достоверного результата все еще нет | Результат уточняется | BR-17 |

Пропуск до отправки не равен отказу процессинга. Хранить ли пропуск как отдельную попытку, пока не решено. Отмена, возврат и повторная оплата после явного отказа не описаны требованиями; переходы для них не следует придумывать.

Для начислений текущие требования различают оплаченные и неоплаченные данные, но полного перечня статусов и переходов нет. Для привязки жизненный цикл удаления и восстановления также не определен.

## Замечание к текущей Jira

В SCRUM-2168, критерий 1, сейчас написано «при активном правиле, сумме, лимиту и достаточных средствах». Для устранения неоднозначности рекомендуется заменить на «при активном правиле, сумме начисления больше нуля и не выше лимита и достаточных средствах». Это восстанавливает проверку из первоначальной редакции и согласуется с SCRUM-2166. Jira этим документом не изменяется.
